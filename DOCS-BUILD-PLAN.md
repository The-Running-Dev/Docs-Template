# Docs Build Refactor Plan

Last updated: 2026-07-25

Build the docs static site **inside the published base image** using a GitHub
Actions job-level `container:`, instead of doing a `docker build` (Docker-in-the-
runner) and extracting artifacts with the Docker CLI. The base image already
carries the full template under `/template` with `node_modules` installed, so CI
only needs to overlay the caller's `./docs` and run the build. The split
`docs-ci` / `docs-deploy` workflows call the in-image `docs-build.ps1`; local
preview stays on `docs.ps1`; `setup-docs.ps1` is a pure orchestrator.

## Execution Model

- **CI build environment = the base image itself.** Workflows run steps inside
  `container: ghcr.io/the-running-dev/docs-template:latest`.
- **No `docker build`, no `docker create/cp/start/rm`.** The container job _is_
  the run; the build is a plain script call.
- **Overlay:** the caller's `./docs` is copied recursively over `/template`,
  overriding `docusaurus.config.ts`, `sidebar.ts`, and `docs/**`.

  | Caller (in repo)              | Overlaid onto                     |
  | ----------------------------- | --------------------------------- |
  | `docs/docusaurus.config.ts`   | `/template/docusaurus.config.ts`  |
  | `docs/sidebar.ts`             | `/template/sidebar.ts`            |
  | `docs/docs/**` (markdown)     | `/template/docs/**`               |

- **PowerShell in the image.** The base image (Alpine/musl) gets PowerShell
  installed and set as the default build shell so `.ps1` scripts run in-image and
  in the container jobs.

## Locked Decisions

- **`Dockerfile` (root):** installs Alpine/musl PowerShell + runtime deps, sets
  `SHELL ["pwsh", ...]`; keeps the runtime `CMD` (`pnpm run start:docker`).
- **`docs-build.ps1`:** in-image build orchestrator (no Docker CLI). Overlay
  `./docs` → `/template`, `pnpm run build`, copy `/template/artifacts` to
  `-OutputPath` in the workspace.
- **`docs.ps1`:** run-only local live server. Runs the base image (pulls if
  missing) and bind-mounts `./docs` over `/template` for hot reload. No build.
- **`setup-docs.ps1`:** orchestration only. Scaffolds the `docs/` overlay
  (`docs/docs/index.md` + optional `docusaurus.config.ts` / `sidebar.ts` seeded
  from the template) and installs the workflows. No Docker, no Dockerfile
  scaffold.
- **Workflows:** split into `docs-ci` (verify) and `docs-deploy` (deploy), each
  `workflow_call` + `workflow_dispatch`, both running inside the base-image
  container job. No push/PR triggers — the main workflow drives them via `uses:`.
- **`setup-docs-workflow.ps1`:** copies **both** workflow templates; does **not**
  overwrite existing files (skips with a message) unless `-Overwrite`.
- **Removed:** `scripts/template/Dockerfile`, `scripts/template/.dockerignore`,
  and `scripts/template/docs.yml` (the base image is the only build environment).
- **`PSModule/PSModule.psd1`:** untouched (regenerated by tooling).

## Tasks

### 1) `Dockerfile` (root): PowerShell in the base image

- [x] Install the Alpine/musl PowerShell tarball + native runtime deps.
- [x] Symlink `pwsh` onto PATH; set `SHELL ["pwsh", "-Command", ...]`.
- [x] Keep `pnpm install --frozen-lockfile` (with explicit `$LASTEXITCODE`
      check) and the `rm -rf /template/docs` step (as `Remove-Item`).

Acceptance: the built image can run `pwsh /template/scripts/docs-build.ps1`.

### 2) `scripts/docs-build.ps1` (in-image overlay + build)

- [x] Params: `-SourceDocs './docs'`, `-TemplateDir '/template'`,
      `-OutputPath 'artifacts/docs'`.
- [x] Recursively overlay `SourceDocs` over `TemplateDir`.
- [x] `pnpm run build` in `TemplateDir`; strict `$LASTEXITCODE` handling.
- [x] Copy `/template/artifacts` to `-OutputPath` in the workspace.

Acceptance: run inside the base image, produces the static site under the output
path.

### 3) `scripts/docs.ps1` (run-only local live server)

- [x] Remove all build logic (`-BuildOnly`, `-BaseImage`, `docker build`).
- [x] Params: `-Port` (3000), `-Tag` (base image), `-ProjectDir`.
- [x] Pull the image if missing; bind-mount `./docs/docs`, and
      `docusaurus.config.ts` / `sidebar.ts` when present.

Acceptance: `./scripts/docs.ps1` serves `http://localhost:3000/docs` with hot
reload; a missing/unpullable image throws a helpful error.

### 4) `scripts/setup-docs.ps1` (orchestration only)

- [x] Remove the inline Docker block and Dockerfile scaffold.
- [x] Scaffold `docs/docs/index.md` (README or stub) + seed optional
      `docs/docusaurus.config.ts` / `docs/sidebar.ts` from the template.
- [x] Install workflows unless `-SkipWorkflow`; forward `-Overwrite`.

Acceptance: one call scaffolds the overlay and installs both workflows;
`-SkipWorkflow` runs the scaffold subset.

### 5) Split workflows: `docs-ci.yml` + `docs-deploy.yml`

- [x] `docs-ci.yml` (verify): `workflow_call` + `workflow_dispatch`,
      `contents: read` / `packages: read`, job-level `container:` (base image +
      GHCR credentials), `defaults.run.shell: pwsh`. Steps: checkout →
      `docs-build.ps1`. No upload/deploy.
- [x] `docs-deploy.yml` (deploy): adds `pages: write` / `id-token: write`,
      `concurrency: github-pages`, `configure-pages` → `docs-build.ps1` →
      `upload-pages-artifact` → `deploy-pages`.
- [x] No `pull_request` / `push` triggers.

Acceptance: the main workflow can `uses:` either to verify or deploy; each is
runnable from the Actions tab; neither runs on push/PR directly.

### 6) `scripts/setup-docs-workflow.ps1` (copy both, no overwrite)

- [x] Resolve both templates from `scripts/template`.
- [x] Copy both into `.github/workflows`; skip existing files (no throw); keep
      `-Overwrite`.

Acceptance: copies missing workflow(s), leaves existing untouched unless
`-Overwrite`.

## Out of Scope (this pass)

- Wiring the caller's main workflow to `uses:` the split workflows.
- `PSModule/PSModule.psd1` edits (regenerated by tooling).
- How a caller's CI obtains the packaged scripts (handled by PSModule packaging).
