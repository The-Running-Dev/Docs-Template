# Docs Build Refactor Plan

Last updated: 2026-07-25

Extract the docs build logic out of the workflow into a reusable
`docs-build.ps1`, split responsibilities cleanly across the PowerShell scripts,
split the single docs workflow into caller-driven `docs-ci` and `docs-deploy`
workflows, and shape `setup-docs.ps1` into a pure orchestrator that an external
caller can invoke through the `DocusaurusTemplate` PSModule.

## Goals

- Provide common, reusable scripts to an external caller through the PSModule.
- One entry point (`setup-docs`) that stands up the Docusaurus-in-Docker setup
  for the caller's local repository: scaffold + build image + install workflows.
- Keep each script single-purpose; remove duplicated Docker logic.
- Let the caller's **main** workflow decide when to verify vs deploy the docs.
- Execution model: **on the host**, using the host Docker daemon.

## Packaging

The template assets moved under `scripts/` so they ship with the packaged
scripts through the PSModule:

- `template/` -> **`scripts/template/`** (flattened; no `.github/workflows/`
  nesting).
- Template files now live at `scripts/template/*`, e.g.
  `scripts/template/Dockerfile`, and the workflow templates
  `scripts/template/docs-ci.yml` and `scripts/template/docs-deploy.yml`
  (split from the former `scripts/template/docs.yml`).
- Scripts resolve template assets relative to `$PSScriptRoot/template`.

## Locked Decisions

- `docs-build.ps1` scope: **build image + extract static site** (build-only).
- `docs.ps1`: **kept, run-only** (live server + hot reload); no build logic.
- `setup-docs.ps1`: **orchestration only**; inline Docker block removed.
- Dockerfile source: caller's local `docs/Dockerfile` if present, else
  **`scripts/template/Dockerfile`** (used verbatim — `COPY . .` + frozen-lockfile
  install).
- Workflows: **split into `docs-ci` (verify) and `docs-deploy` (deploy)**, each
  declaring **`workflow_call` + `workflow_dispatch`** — the main workflow calls
  the right one (verify vs deploy) via `uses:`, and each can still be run
  manually. No push/PR triggers.
- `setup-docs-workflow.ps1`: copies **both** workflow templates into the caller
  repo and **does not overwrite** files that already exist.
- `PSModule/PSModule.psd1`: **untouched** (regenerated by
  `SubZeroDev.ContainerPSGenerator`).

## Tasks

### 1) New `scripts/docs-build.ps1` (build + extract, build-only)

- [ ] Params: `-ProjectDir '.'`, `-Tag`, `-BaseImage`, `-OutputPath 'artifacts/docs'`,
      `-Dockerfile` (optional override).
- [ ] Resolve Dockerfile: caller's `docs/Dockerfile` if present, else
      `scripts/template/Dockerfile` (located via `$PSScriptRoot/template`).
- [ ] Build context = project root (matches `scripts/template/Dockerfile`
      `COPY . .` model — differs from the old `docs/` + `COPY . ./docs` behavior).
- [ ] Run its own `docker build` (no delegation to `docs.ps1`).
- [ ] `docker create` -> `docker start --attach` running `pnpm run build`.
- [ ] `docker cp` the static site (`/template/artifacts/.`) to `-OutputPath`.
- [ ] Strict `$LASTEXITCODE` / `throw` handling; `finally` block force-removes the
      build container.

Acceptance criteria:

- Running `./scripts/docs-build.ps1 -Tag docs-site:test` produces the static site
  under `artifacts/docs` with no leftover build container.

### 2) `scripts/docs.ps1` (run-only live server)

- [ ] Remove `-BuildOnly`, `-BaseImage`, and all `docker build` logic.
- [ ] Params: `-Port` (default 3000), `-Tag`, `-ProjectDir`.
- [ ] Always bind-mount `docs/` (+ `docusaurus.config.ts` / `sidebars.ts` when
      present) over the running container for hot reload.
- [ ] Throw a clear "run `docs-build.ps1` first" error if the image tag does not
      exist.
- [ ] Fix stale default tag `gameoflife-docs` -> `docusaurus-docs`.

Acceptance criteria:

- `./scripts/docs.ps1 -Tag <existing-image>` serves `http://localhost:3000/docs`
  and hot-reloads on `docs/` edits; a missing image throws a helpful error.

### 3) `scripts/setup-docs.ps1` (orchestration only)

- [ ] Remove the inline Docker block (`-DockerDocs` / `-Live` / `-BuildOnly`).
- [ ] Default flow: scaffold -> `docs-build.ps1` -> `setup-docs-workflow.ps1`.
- [ ] Scaffold `docs/`, `docs/index.md`, and `docs/Dockerfile` (copied verbatim
      from `scripts/template/Dockerfile`, replacing the old inline heredoc).
- [ ] Escape hatches: `-SkipBuild`, `-SkipWorkflow`.
- [ ] Forward `-ProjectDir`, `-Tag`, `-BaseImage` to the sub-scripts.

Acceptance criteria:

- `Invoke-SetupDocs` on a clean repo scaffolds docs, builds the image, and
  installs the workflows in one call; `-SkipBuild` / `-SkipWorkflow` run subsets.

### 4) Split workflows: `docs-ci.yml` + `docs-deploy.yml`

Replace the former single `docs.yml` with two workflow templates under
`scripts/template/`. Each declares **both** `workflow_call` and
`workflow_dispatch` so the caller's main workflow drives them (verify vs deploy)
via `uses:`, while still allowing manual/API runs. The main workflow decides
when to verify and when to deploy.

- [ ] **`scripts/template/docs-ci.yml` (verify).** Triggers: `workflow_call` +
      `workflow_dispatch`. Permissions: `contents: read`, `packages: read`.
      Steps: checkout -> GHCR login -> verify base image ->
      `./scripts/docs-build.ps1` to build the image and produce the static site.
      No Pages upload, no deploy.
- [ ] **`scripts/template/docs-deploy.yml` (deploy).** Triggers: `workflow_call` +
      `workflow_dispatch`. Permissions add `pages: write`, `id-token: write`;
      `concurrency: github-pages`. Steps: checkout -> GHCR login -> verify base
      image -> `configure-pages` -> `./scripts/docs-build.ps1 -OutputPath artifacts/docs`
      -> `upload-pages-artifact` -> `deploy-pages`.
- [ ] No `pull_request` / `push` / `paths` triggers.
- [ ] Both call `./scripts/docs-build.ps1` (no inline Docker logic, no
      `docs.ps1 -BuildOnly`).

Note: `workflow_call` is the synchronous "main workflow decides" path (nested
run, inline result); `workflow_dispatch` is the manual/API escape hatch. Add
`repository_dispatch` later only if a decoupled custom-event trigger is wanted.

Acceptance criteria:

- The main workflow can `uses:` either workflow to verify or deploy, and each is
  runnable manually from the Actions tab / `gh workflow run`.
- `docs-ci` verifies the docs build without deploying; `docs-deploy` builds and
  deploys to GitHub Pages.
- Neither runs on push/PR directly; the main workflow drives both.

### 5) `scripts/setup-docs-workflow.ps1` (copy both, no overwrite)

- [ ] Resolve both templates from `$PSScriptRoot/template`:
      `docs-ci.yml` and `docs-deploy.yml`.
- [ ] Copy **both** into the caller's `.github/workflows/`.
- [ ] **Do not overwrite** an existing destination file — skip it with a message
      (do not throw). Keep `-Overwrite` to force replacement of both.
- [ ] Update path candidates for the new `scripts/template/` location.

Acceptance criteria:

- Running against a caller repo copies any missing workflow(s) and leaves
  existing ones untouched unless `-Overwrite` is passed.

## Out of Scope (this pass)

- `PSModule/PSModule.psd1` edits — regenerated by tooling.
- The exact mechanism by which a caller's CI obtains the packaged scripts at run
  time (assumed handled by PSModule packaging of `scripts/`).
